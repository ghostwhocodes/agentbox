# agentbox

`agentbox` is a workspace-local context manager for independent git repos.

It keeps AI or tool-specific state out of a leaf repo's git history while still making that state available inside the repo through bind mounts.

The CLI targets a workspace directory, not the `agentbox` source checkout. By default it starts at the current directory and discovers the nearest parent workspace. Use `--workspace <path>` to point at an exact workspace root.

## What It Does

- Registers repos by clone source, not by adopting an existing checkout.
- Materializes managed repos as fresh clones under `repos/<repo-id>/`.
- Stores workspace-owned context under `context/<repo-id>/`.
- Projects context back into materialized repos through writable bind mounts.
- Supports multiple mounts per repo, not just `ai/`.
- Supports workspace-local templates with persisted repo-template bindings and default mounts.
- Includes `doctor` checks with limited auto-fix behavior for workspace structure and stale runtime bookkeeping.

Detaching a repo preserves `context/<repo-id>/` on disk, but it removes the repo registration and mount mappings from the manifest. Reattaching the same repo id does not automatically restore mount rules; re-add them or reapply a template.

## Workspace Layout

```text
agentbox/
  agentbox.toml
  .gitignore
  .agentbox/          # internal state, created on demand, ignored
  context/
    <repo-id>/
  repos/
    <repo-id>/
  templates/
    <template-id>/
      template.toml
      context/
```

`repos/` and `.agentbox/` are ignored by the outer workspace repo. `context/`, `templates/`, and `agentbox.toml` are tracked.

The workspace manifest uses `version = 1` and persists three top-level sections:

```toml
version = 1

[repos.demo]
source = "git@github.com:org/demo.git"

[repo_templates.demo]
template = "default"

[[repo_mounts]]
repo_id = "demo"
context = "ai"
repo = "ai"
```

`repo_templates` records the last applied template binding for a repo. `status` and `show` do not print that binding.

Runtime mount ownership receipts are advisory state under `.agentbox/state/`. They are ignored with `.agentbox/` and can be regenerated by later mount operations.

## Workspace Targeting

Two common ways to run commands:

```bash
cd /path/to/my-workspace
agentbox init
```

```bash
agentbox --workspace /path/to/my-workspace init
```

Without `--workspace`, `agentbox` searches upward from the current directory for the nearest parent workspace. If none is found, it uses the current directory so `agentbox init` initializes exactly where you run it.

`--workspace` always means that exact directory. It does not search parent directories for a workspace root.

## Clone Source Rules

Allowed forms:

- `https://...`
- `ssh://...`
- `git@github.com:org/repo.git`
- `file://...`

Disallowed forms:

- `~/src/repo`
- `../repo`
- treating an arbitrary local checkout as the managed source of truth

## Build And Test

```bash
cargo build
cargo run -- --help
cargo run -- --workspace /path/to/my-workspace status
cargo test
cargo test --test workflow_integration
just ci
cargo test --features privileged-tests --test privileged_bind_mount
```

`just ci` runs `fmt`, a warning-denied build, strict clippy, tests, and `cargo llvm-cov` with minimum thresholds of `80%` line coverage and `80%` region coverage for the normal non-privileged test path.

The privileged bind-mount test target is separate because it requires Linux bind-mount capability, typically `CAP_SYS_ADMIN`, so it is not part of the default coverage gate.

## Dependencies

Runtime dependencies are intentionally minimal:

- `camino` — UTF-8 path handling
- `clap` — CLI argument parsing
- `nix` — Linux mount/unmount syscalls
- `serde` / `toml` — manifest serialization
- `thiserror` — error type derivation

No regex engine is used; slug and clone-source validation is hand-rolled for fast compilation and small binary size.

## Safety

The crate forbids all `unsafe` code (`#![forbid(unsafe_code)]`). Mount and unmount operations delegate to the `nix` crate, which encapsulates the necessary syscalls.

## Scope

Included in v1:

- workspace-local repo registration
- materialization and dematerialization of managed clones
- writable bind mounts
- import of repo-created directories into workspace ownership
- workspace-local templates
- persisted repo-template bindings plus template-derived mount expansion
- doctor checks, structural fixes, stale template-binding cleanup, and stale mount-receipt cleanup

Explicitly out of scope:

- global config
- profiles
- repo scaffolding
- readonly mount modes
- automatic background sync

## Error Handling

Mount-table operations (reading `/proc/self/mountinfo`) are handled differently by read-only and state-changing commands:

- **Read-only commands** (`status`, `show`, `doctor`) skip mount-table reads when no repo both exists locally and has configured mounts. When mount inspection is needed but the mount table is unreadable, these commands degrade gracefully: `status` and `show` report mount state as "unknown", and `doctor` emits a warning and skips mount-specific checks.
- **State-changing commands** (`mount`, `unmount`, `dematerialize`, `detach --force`) fail hard when the mount table cannot be read, since they need accurate mount state to operate safely.

Mount ownership receipts are stored as advisory runtime state in `.agentbox/state/mount-ownership.toml`. `mount` and `import-mount` create the bind mount first, then best-effort record the live mount ID, source root, and filesystem type. Receipt write failures do not roll back a successful mount.

Destructive teardown is conservative. `unmount` and `detach --force` only auto-unmount same-source live mounts when the live mount still matches the receipt. If a mount was manually remounted, restored after a reboot, or recreated by another tool, it may still point at the expected source but have a different live mount ID; agentbox treats that as unverified and refuses to tear it down by default. Use `--unsafe-unmount` only when you have inspected the live mount and intentionally want agentbox to unmount it anyway.

## Filesystem Support

`agentbox` relies on standard Linux bind mounts plus `/proc/self/mountinfo` inspection. Mount inspection is intended to work with common Linux filesystems including:

- `ext4`
- `zfs`
- `btrfs` including typical subvolume-based mount layouts

Other Linux filesystems may work, but are less explicitly exercised. Treat them as best-effort and verify `status`, `show`, `list-mounts`, `mount`, and `unmount` on your target system.
